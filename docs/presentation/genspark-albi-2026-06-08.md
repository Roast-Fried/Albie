## 1. Genspark AI Slides 생성 프롬프트 (복사용)

```
당신은 IT 발표 전문 슬라이드 디자이너입니다. 아래 명세에 맞춰 발표용 슬라이드 덱을 만들어 주세요.

[주제]
"알비(Albi) — 자연어로 한 줄 쓰면 끝나는 AI 음주 기록 앱" 대학 강의(모바일 앱 프로그래밍) 팀 프로젝트 발표.

[청중 / 목적]
- 청중: 교수님 + 같은 수업 수강생 (개발 지식 있음)
- 목적: 앱의 가치 + 기술 아키텍처 + 강의에서 배운 개념의 적용을 10분 안에 설득력 있게 전달
- 톤: 깔끔하고 전문적이되, 첫 도입은 공감되는 일상 예시로 가볍게

[분량 / 형식]
- 슬라이드 12장 (표지 포함)
- 16:9 와이드, 슬라이드당 핵심 메시지 1개 + 불릿 3~4개 이내, 텍스트는 간결하게
- 발표자가 말로 채우는 구조 — 슬라이드에 문장을 빽빽이 넣지 말 것
- 다이어그램/아이콘/스크린샷 placeholder를 적극 활용

[디자인 가이드]
- 무드: 위스키 바의 따뜻하고 차분한 분위기 (술/건강을 다루는 앱)
- 메인 컬러: 앰버 골드 #B8731A, 포인트 #E0A857, 다크 배경 옵션 #15110D(피트 블랙), 크림 배경 #FBF6EE
- 폰트: 한글 고딕 계열(Pretendard 느낌), 제목 굵게
- 아이콘 스타일: 라인 아이콘, 미니멀

[슬라이드 구성 — 아래 12장을 정확히 이 순서로]

1. 표지
   - 큰 제목: "알비(Albi)"
   - 부제: "자연어로 한 줄 쓰면 끝나는 AI 음주 기록 비서"
   - 하단: 모바일 앱 프로그래밍 / 팀 김태겸·곽지한 / Flutter
   - 비주얼: 위스키 잔 + 채팅 말풍선이 결합된 일러스트

2. 왜 만들었나 (문제 정의)
   - 메시지: "음주 기록은 귀찮아서 작심삼일이 된다"
   - 불릿: 항목별 폼 입력(술 종류·양·도수·안주·장소)이 번거로움 / 기록이 끊기면 데이터가 무의미 / 정작 알고 싶은 건 "내가 얼마나 마셨나"
   - 비주얼: 복잡한 입력 폼 vs 한 줄 텍스트 대비

3. 해결: 한 줄이면 끝
   - 메시지: "어제 강남에서 소주 2병에 삼겹살" → 자동으로 구조화
   - 흐름(가로 4단계): 자연어 입력 → AI 파싱 → 검토·수정 → 저장
   - 비주얼: 입력 한 줄이 카드(술/양/도수/안주/장소)로 펼쳐지는 모습

4. 핵심 차별점 3가지
   - ① 자연어 AI 파싱: 폼이 아니라 말하듯 입력
   - ② AI가 없어도 동작: 규칙 기반 파서가 항상 대비 (오프라인/키 없음/실패 시 fallback)
   - ③ 저장 전 반드시 검토 화면: AI를 맹신하지 않는 안전 설계 (자동 저장 금지)
   - 비주얼: 3개 카드 아이콘

5. 아키텍처 (MVVM + Riverpod)
   - 메시지: "역할이 분리된 단방향 구조"
   - 다이어그램: View → ViewModel → Repository → SQLite (한 방향 화살표)
   - 불릿: View는 화면만 / ViewModel이 상태·로직 / Repository가 DB / 상태관리는 Riverpod
   - 비주얼: 레이어 다이어그램

6. AI 파싱 엔진 (ParseOrchestrator)
   - 메시지: "AI를 쓰되, AI에 의존하지 않는다"
   - 흐름: 입력 → (AI 사용 가능?) → 예: Gemini 호출 → 실패하면 규칙 기반 파서로 자동 전환
   - 불릿: 재시도·취소(CancelToken) 지원 / 사용량 할당량 관리 / AI 시도 여부를 사용자에게 투명하게 표시
   - 비주얼: 분기 플로우차트 (AI 경로 / fallback 경로)

7. 데이터 설계
   - 메시지: "안정적인 로컬 우선 데이터베이스"
   - 불릿: SQLite 8개 테이블 + 트랜잭션으로 원자성 보장 / 술 마스터 553종 시드(한국 시장 브랜드 포함) / 음식 사전 36종 / 수정 시 기록 ID 보존(연결 데이터 유실 방지)
   - 비주얼: 테이블 관계도 간략 + "553종" 큰 숫자 강조

8. 주요 화면 둘러보기
   - 메시지: "기록부터 회고까지"
   - 6분할 스크린샷 placeholder: 홈(입력) / 검토·수정 / 기록 목록 / 캘린더 / 아카이브(술별) / 통계
   - 캡션은 짧게

9. 건강 인사이트 & 리마인더
   - 메시지: "단순 기록을 넘어 행동으로"
   - 불릿: 표준잔 계산(한국 기준 1잔=순알코올 8g)으로 과음 신호 / 카테고리별 통계 차트 / 로컬 알림 4종(주간 요약·3일 미기록 리마인드·새벽 음주 다음날·주간 과음 경고)
   - 비주얼: 통계 차트 + 알림 카드

10. 기술적 도전과 해결
   - 메시지: "정상보다 비정상을 먼저 설계했다 (failure-path first)"
   - 불릿: 통일된 에러 계층(sealed class)으로 누락 없는 예외 처리 / 개인정보 보호 — 기록 삭제 시 AI 원문 데이터까지 정리 / 클라우드 백업은 선택적(키 없으면 자동 비활성, 앱은 정상 동작)
   - 비주얼: 방패/체크 아이콘

11. 강의 개념의 적용 (배운 것)
   - 메시지: "수업에서 배운 핵심 주제를 실제로 구현"
   - 불릿: 상태관리(Riverpod) / 로컬 DB 두 방식 비교 — sqflite vs Drift ORM(격리 데모 모듈) / 외부 REST API 연동(Dio·재시도) / 권한·로컬 알림 / 클라우드(Supabase)
   - 비주얼: 개념 ↔ 구현 매핑 표

12. 팀 역할 & 마무리
   - 좌: 역할 분담 — 김태겸(자연어 파싱·데이터베이스·AI 연동) / 곽지한(UI·디자인·UX)
   - 우: 배운 점 한 줄 + 향후 계획(클라우드 동기화 본격화, 디자인 리뉴얼)
   - 하단: "감사합니다 — 알비(Albi)" 클로징
   - 비주얼: 표지 일러스트 재사용 + 따뜻한 마무리 톤

[작성 규칙]
- 각 슬라이드 제목은 위의 "메시지"를 짧고 임팩트 있게 다듬어 사용

- 전문 용어는 한국어 우선, 필요한 기술명(Flutter, Riverpod, SQLite, Gemini, Drift, Supabase)만 영문 유지
- 마지막에 발표자 노트는 넣지 말 것 (대본은 별도 제공됨)
```

## 2. 슬라이드별 발표 대본 (speaker script)

> 화자 표기: 🟠 곽지한(UI/UX) · 🔵 김태겸(파싱/DB) · 슬라이드당 약 40~55초
> 자연스럽게 말하는 구어체. 괄호는 행동/전환 큐.

### S1. 표지 — 🟠 곽지한 (약 25초)
"안녕하세요. 저희는 '알비'를 만든 김태겸, 곽지한입니다. 알비는 '알코올 비서'의 줄임말인데요, 술 마신 걸 그냥 한 줄로 말하듯 적으면 AI가 알아서 정리해 주는 기록 앱입니다. Flutter로 만들었고요, 지금부터 어떤 문제를 어떻게 풀었는지 보여드리겠습니다."

### S2. 왜 만들었나 — 🟠 곽지한 (약 45초)
"음주 기록 앱들 한 번씩 써보셨을 텐데, 보통 작심삼일로 끝납니다. 이유가 뭐냐면, 마실 때마다 술 종류 고르고, 양 넣고, 도수 넣고, 안주에 장소까지 일일이 입력해야 하거든요. 한두 번은 하는데 그게 쌓이면 안 하게 돼요. 그런데 기록이 끊기면 데이터가 의미가 없어집니다. 정작 사용자가 궁금한 건 '내가 요즘 얼마나 마셨지?' 하나인데, 그걸 보려면 매번 귀찮은 입력을 견뎌야 하는 모순이 있었습니다. 저희는 이 '입력 마찰'을 없애는 데 집중했습니다."

### S3. 해결: 한 줄이면 끝 — 🟠 곽지한 (약 45초)
"알비의 핵심은 이겁니다. (슬라이드 가리키며) '어제 강남에서 소주 2병에 삼겹살' — 이렇게 평소 말하듯 한 줄만 쓰면 됩니다. 그러면 앱이 자동으로 '소주, 2병, 도수, 안주는 삼겹살, 장소는 강남, 날짜는 어제'로 쪼개서 카드로 보여줘요. 흐름은 네 단계입니다. 자연어로 입력하면, AI가 파싱하고, 사용자가 한 번 검토·수정한 뒤, 저장됩니다. 입력의 번거로움은 없애되, 정확성은 검토 단계로 잡는 구조예요."

### S4. 핵심 차별점 3가지 — 🔵 김태겸 (약 50초)
"여기서 저희가 신경 쓴 세 가지를 말씀드리겠습니다. 첫째, 자연어 AI 파싱입니다. 폼이 아니라 말로 입력해요. 둘째, 이게 중요한데, AI가 없어도 동작합니다. 인터넷이 끊겼거나, API 키가 없거나, AI 호출이 실패해도 규칙 기반 파서가 곧바로 받아줍니다. 그래서 앱이 절대 '먹통'이 되지 않습니다. 셋째, 저장 전에 반드시 검토 화면을 거칩니다. AI가 틀릴 수 있으니까요. AI를 쓰되 맹신하지 않는, 자동 저장을 일부러 막아둔 안전 설계입니다."

### S5. 아키텍처 — 🔵 김태겸 (약 50초)
"구조는 MVVM 패턴을 따랐습니다. (다이어그램 가리키며) 화면(View)은 보여주기만 하고, 실제 상태와 로직은 ViewModel이, 데이터베이스 접근은 Repository가 담당합니다. 화살표가 한 방향이죠. 화면이 데이터베이스를 직접 건드리는 일이 없도록 강제했습니다. 상태관리는 Riverpod을 썼고요. 이렇게 역할을 분리하니까, 한 부분을 고쳐도 다른 데가 안 깨지고, 두 명이 나눠서 작업하기도 훨씬 수월했습니다."

### S6. AI 파싱 엔진 — 🔵 김태겸 (약 50초)
"AI 파싱의 내부를 조금 더 보겠습니다. 핵심 원칙은 'AI를 쓰되 AI에 의존하지 않는다'입니다. 입력이 들어오면 먼저 AI를 쓸 수 있는 상태인지 확인하고, 가능하면 Gemini를 호출합니다. 만약 실패하면 그 순간 규칙 기반 파서로 자동 전환됩니다. 호출이 너무 오래 걸리면 사용자가 취소할 수도 있고요, API 사용량 할당량도 관리합니다. 그리고 'AI를 실제로 시도했는지' 여부를 사용자에게 투명하게 알려줘서, 결과를 믿을지 말지 판단할 수 있게 했습니다. 이 파싱 로직은 화면이나 ViewModel이 아니라 별도 모듈로 완전히 분리해 뒀습니다."

### S7. 데이터 설계 — 🔵 김태겸 (약 45초)
"데이터는 로컬 우선으로 SQLite를 썼습니다. 테이블이 8개인데, 기록 하나를 저장할 때 술·안주·파싱 로그가 한꺼번에 들어가야 해서 트랜잭션으로 묶어 원자성을 보장했습니다. 그리고 술 데이터가 미리 553종 들어 있습니다. 위스키, 와인, 맥주부터 소주, 막걸리까지 한국 시장 브랜드를 직접 큐레이션해서 넣었어요. 음식 사전도 36종 있고요. 또 기록을 수정할 때 항목 ID를 보존하도록 해서, 연결된 테이스팅 노트 같은 데이터가 유실되지 않게 처리했습니다."

### S8. 주요 화면 둘러보기 — 🟠 곽지한 (약 45초)
"실제 화면을 빠르게 보여드리겠습니다. (스크린샷 순서대로) 홈에서 한 줄 입력하고, 검토 화면에서 파싱 결과를 확인·수정합니다. 기록 목록은 월별로 묶여서 보이고, 캘린더로도 음주일을 한눈에 볼 수 있어요. 아카이브는 '내가 어떤 술을 얼마나 마셨나'를 술 종류별로 모아주고, 통계 화면에서는 카테고리 비중을 차트로 보여줍니다. 기록하는 즐거움부터 돌아보는 재미까지 한 흐름으로 이어지게 설계했습니다."

### S9. 건강 인사이트 & 리마인더 — 🟠 곽지한 (약 50초)
"알비는 단순 기록을 넘어서 행동까지 돕습니다. 마신 술을 한국 기준 '표준잔'으로 환산하는데, 1 표준잔이 순알코올 8그램이에요. 이걸로 과음 신호를 잡아냅니다. 통계는 차트로 보여주고요. 그리고 로컬 알림이 네 가지 있습니다. 매주 일요일 주간 요약, 3일 동안 기록이 없으면 가볍게 리마인드, 새벽에 마신 다음 날 낮에 입력 알림, 그리고 한 주에 너무 많이 마셨으면 건강 경고를 보냅니다. 기록을 '하게 만들고', 더 나아가 마시는 습관을 돌아보게 만드는 장치들입니다."

### S10. 기술적 도전과 해결 — 🔵 김태겸 (약 50초)
"개발하면서 가장 신경 쓴 원칙은 'failure-path first', 즉 정상 동작보다 비정상 상황을 먼저 설계하는 것이었습니다. 첫째, 에러를 sealed class로 한 곳에 모아서, 새로운 에러 종류가 생기면 처리 누락이 컴파일 단계에서 잡히게 했습니다. 둘째, 개인정보 보호인데요, 기록을 삭제하면 AI에 보냈던 원문 데이터까지 같은 트랜잭션에서 정리됩니다. 셋째, 클라우드 백업(Supabase)은 선택 기능으로 만들어서, 키가 없으면 자동으로 꺼지고 앱 본체는 멀쩡히 동작합니다. 어떤 상황에서도 사용자 데이터가 안전한 쪽으로 설계했습니다."

### S11. 강의 개념의 적용 — 🔵 김태겸 / 🟠 곽지한 함께 (약 45초)
"이 프로젝트에는 수업에서 배운 개념들이 거의 다 들어가 있습니다. 상태관리는 Riverpod으로, 로컬 DB는 sqflite로 구현하면서, 같은 기능을 Drift라는 ORM으로도 따로 만들어서 두 방식을 비교하는 격리 데모 모듈을 넣었습니다. 외부 REST API 연동은 Gemini 호출에 재시도 로직까지 붙여서 다뤘고요, 권한과 로컬 알림, 그리고 클라우드 연동까지 — 강의 주제를 실제 제품 안에서 직접 적용해 본 게 가장 큰 수확이었습니다."

### S12. 팀 역할 & 마무리 — 🟠 곽지한 (약 35초)
"마지막으로 역할 분담입니다. 김태겸 학생이 자연어 파싱과 데이터베이스, AI 연동을 맡았고, 저 곽지한은 UI와 디자인, 사용자 경험을 담당했습니다. 저희가 배운 건, '편리함과 정확함은 검토 단계 하나로 양립할 수 있다'는 점이었어요. 앞으로는 클라우드 동기화를 본격화하고 디자인도 더 다듬을 계획입니다. 이상, 한 줄이면 끝나는 음주 기록 앱 '알비' 발표를 마치겠습니다. 감사합니다."
