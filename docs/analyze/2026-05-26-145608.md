## 핵심 패턴

### 관찰된 강점
1. **MVVM + Riverpod 완전 분리** — View 에서 `RepoProvider` 직접 접근 0건 (grep 검증). 모든 데이터 접근이 ViewModel/FutureProvider 경유.
2. **트랜잭션 우선 설계** — `DrinkLogRepository.save/update/delete` 모두 `_db.transaction()` 으로 log+entries+foods 원자성 보장.
3. **AI-first, local fallback** — `ParseOrchestrator` 가 Gemini 가용성 체크 후 `LocalRuleParser` 자동 fallback. wasAiAttempted 플래그로 배너 표시 제어.
4. **sealed AppError 계층** — exhaustive switch 강제, Repository 경계에서만 try-catch (`drink_log_repository.dart`, `parse_job_repository.dart`, `ai_config_repository.dart`, `tasting_note_repository.dart`).
5. **invalidate 일괄 전략** — DraftReview save 후 8개 provider 일괄 invalidate (`draft_review_viewmodel.dart:121-130`), LogList refresh 도 대칭 유지 주석 명시.
6. **Gemini retry + CancelToken** — `gemini_client.dart:53-70` exponential backoff (1s→2s) + 5xx/timeout 만 retry + 429 fallback 위임 + cancel 시 즉시 rethrow.

### 관찰된 약점 (Codex finding 추가)
- **LocalRuleParser 정규식 비대칭** (C1/C2): 명시 도수 미파싱 + split trigger 와 quantity 추출 정규식 범위 불일치.
- **CancelToken 전파 불완전** (C3): 네트워크 호출에만 cover, `_prepareImage` decode/resize 단계는 미적용.
- **Quota race** (C4): check / API / increment 가 별도 트랜잭션.
- **statsPeriodProvider 전역 stale state** (C8): autoDispose 없는 StateProvider.
- **테스트 격리** (Agent 3): ProviderContainer 미사용 → 동시 실행 시 cache 오염 risk.
