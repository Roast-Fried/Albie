## 핵심 패턴 (실제 관찰 — 모두 CONFIRMED)

- **상태관리**: Riverpod StateNotifier(Home/DraftReview) + AsyncNotifier(LogList/Archive/AiConfig/Notification/Theme/Account/AppSettings) + Future/StateProvider.family. `autoDispose` 는 기본 미사용(IndexedStack 탭 유지), `statsProvider` 만 예외 적용 (statsPeriodProvider cascade 이유 명시).
- **레이어**: View → ViewModel → Repository 엄격 준수. `grep RepoProvider lib/views/` → **0 위반**.
- **데이터**: 모든 Repository 쓰기 = `_db.transaction` + `catch DatabaseException → DatabaseError`. update() 는 entry id 보존 upsert (tastingNote CASCADE 방지).
- **에러**: sealed AppError 4 subclass + Dart3 exhaustive switch. parse_orchestrator 의 `_classifyAiError()` DioException 분류.
- **AI optional**: ParseOrchestrator 가 disabled/keyMode/키없음 3단계 → LocalRuleParser fallback (throw 없음). `wasAiAttempted` 플래그로 실패배너 표시 제어.
- **개인정보**: 단건 삭제 시 같은 트랜잭션에서 parseJob raw* NULL(`clearRawByLogId`), 전체삭제는 `deleteAll()` 행 삭제.
- **Supabase**: offline-first (`fetch → confirm → wipe → apply`), AuthException → ValidationError/NetworkError 매핑(PII 미노출).
- **Drift 데모**: 메인 DB 와 완전 격리(별도 파일/경로/FK없음), ViewModel 경유 규칙 동일 적용.
- **코드스멜**: `reactive(` 0건, WidgetRef anti-pattern 0건, provider 정의 선언 기반 일관.
