## 1. Executive Summary

알비는 **"어제 강남에서 소주 2병에 삼겹살"** 같은 자연어 한 줄을 입력하면, 술 종류·수량·도수·안주·장소·날짜를 자동으로 구조화해 음주 기록 초안을 만들어 주는 모바일 앱이다. 핵심 가치는 **입력 마찰 제거**에 있다.

설계 철학은 세 가지로 요약된다.

1. **자연어 AI 파싱** — 항목별 폼 입력 대신 말하듯 한 줄로 입력한다.
2. **AI에 의존하지 않는다** — AI(Gemini)가 없거나 실패해도 규칙 기반 파서(LocalRuleParser)가 항상 대체하므로 앱이 절대 멈추지 않는다.
3. **저장 전 반드시 검토** — AI 결과를 자동 저장하지 않고, 사용자가 검토·수정한 뒤에만 저장한다(자동 저장 금지).

기술적으로는 Flutter + Riverpod 기반 MVVM, sqflite 로컬 DB(8 테이블), 그리고 선택적 클라우드 백업(Supabase)·로컬 알림으로 구성된다. 모든 데이터는 단말에 우선 저장(Local-first)되며, 비정상 상황(네트워크 실패·AI 실패·삭제 시 개인정보)을 먼저 설계하는 **failure-path first** 원칙을 따른다.

## 2. 프로젝트 개요

### 2.1 기획 배경
술을 마신 뒤에는 무엇을 얼마나 마셨는지 금세 흐려진다. 특히 위스키처럼 브랜드·숙성연수·도수 차이가 큰 술은 기억만으로 정리하기 어렵다. 그러나 기존 음주 기록 앱들은 술 종류·양·도수·안주·장소를 매번 항목별로 입력해야 해서 번거롭고, 그 번거로움 때문에 기록이 끊기면 쌓인 데이터마저 무의미해진다. 알비는 이 **입력 마찰**을 자연어 입력으로 없애고, 정확성은 **검토 단계**로 확보하는 방식으로 문제를 해결한다.

### 2.2 목적 / 가치 제안
- **빠른 입력**: 폼이 아닌 자연어 한 줄로 기록한다.
- **끊기지 않는 기록**: AI가 없어도 동작하므로 어떤 환경에서도 기록할 수 있다.
- **신뢰할 수 있는 데이터**: 저장 전 검토로 오기록을 막는다.
- **회고와 통찰**: 마셔본 술을 아카이빙하고, 통계·캘린더·표준잔으로 음주 패턴을 돌아본다.

### 2.3 타깃 사용자 (페르소나)
- **위스키 애호가** — 브랜드·연산별로 마셔본 술을 차곡차곡 기록·회고하고 싶다.
- **술자리 기록형** — 술자리 후 "뭘 마셨는지" 자주 잊어 가볍게 남기고 싶다.
- **개인 아카이브 선호형** — 복잡한 커뮤니티·소셜보다 빠른 입력과 개인 기록을 선호한다.

### 2.4 범위
**포함**
- 자연어/이미지 기반 기록 초안 생성, 검토·수정·저장
- 테이스팅 노트, 마셔본 술 아카이브, 통계, 음주 캘린더
- 표준잔 기반 건강 신호, 로컬 알림
- 선택적 클라우드 백업·복원(이메일 인증)

**제외**
- 실시간 동기화, 소셜 피드
- 실제 체내 알코올 농도 측정·의학적 건강 판정
- 완전 자동 판정형(검토 없는 자동 저장) 이미지 인식, 정교한 추천 엔진

> 회원가입/로그인·클라우드 백업은 **완전 제외가 아니라 선택 기능**이다. Supabase 자격증명(`.env`) 미설정 시 휴면(dormant) 상태로 로컬 앱처럼 동작하고, 설정 시에만 백업·복원 기능이 활성화된다. 단 실시간 동기화·소셜 피드는 여전히 제외다.

### 2.5 차별점
| 구분 | 일반 기록 앱 | 알비 |
|------|-------------|------|
| 입력 | 항목별 폼 | 자연어 한 줄 |
| AI 장애 시 | 기능 중단 | 규칙 파서로 자동 대체 |
| 저장 방식 | 즉시 저장 | 검토 후 저장 (오기록 방지) |
| 데이터 위치 | 서버 중심 | 로컬 우선(Local-first) + 선택적 백업 |

## 4. 사용자 시나리오 및 화면 흐름

### 4.1 핵심 시나리오

**시나리오 A — 자연어 기록 (AI 연결)**
1. 사용자가 홈 입력창에 "어제 강남에서 글렌피딕 12년 2잔 마셨어" 입력
2. AI(Gemini)가 분석 → 글렌피딕 12년 / 2잔 / 위스키 / 장소: 강남 / 날짜: 어제 로 구조화
3. 검토 화면에서 매칭 결과 확인(✓/⚠ 아이콘, 영문 병기, 추정 수량 경고)
4. 필요한 부분 수정 → 저장 → 홈/목록/통계 갱신

**시나리오 B — 자연어 기록 (AI 미연결/실패)**
1. AI가 비활성이거나 호출 실패
2. LocalRuleParser가 마스터 데이터(553종)·규칙으로 파싱
3. 상단에 "로컬 파서로 처리됨" 경고 배너(AI를 실제 시도한 경우에만)
4. 검토 → 저장 (흐름 동일)

**시나리오 C — 이미지 보조**
1. 병 라벨/메뉴/영수증 사진 첨부
2. AI 이미지 분석 → 초안 제안 (실패 시 텍스트 fallback → 빈 폼)
3. 검토 → 저장

**시나리오 D — 회고**
- 기록 목록(월별 그룹) → 상세(테이스팅 노트·별점) / 아카이브(술별 집계) / 통계(차트) / 캘린더(음주일)

**시나리오 E — 클라우드 백업 (선택)**
- 설정 → 클라우드 백업·동기화 → (`.env` 설정 시) 이메일 로그인 → 백업/복원 / (미설정 시) 안내만

### 4.2 전체 화면 흐름도

```
  [1] 앱 시작 / 홈
       │
       └─▶ [2] 자연어 입력 ─ (AI 연결) ─▶ [3a] AI 파싱 ┐
                 │                                        │
                 └──── (AI 미연결/실패) ─▶ [3b] 로컬 파싱 ┤
   [OPT-A] 이미지 입력 ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─┤
                                                          ▼
                                            [4] 기록 초안 생성
                                                          ▼
                                            [5] 검토 / 수정 / 저장
                                                          ▼
                                            [6] 저장 반영 → [1] 홈 (순환)

  [OPT-B] 설정 / AI 연결 ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─▶ [3a]
  [OPT-C] 더보기 ─▶ 음주 캘린더 ─▶ 날짜 선택 ─▶ 선택일 기록 ─▶ 기록 상세
  [OPT-D] 설정 ─▶ 클라우드 백업 ─ (.env 설정) ─▶ 로그인 ─▶ 백업/복원
                              └─ (.env 미설정) ─▶ "미설정" 안내(dormant)
```

### 4.3 하단 탭 구조
앱은 `IndexedStack` 기반 3개 탭으로 구성되며, 탭 전환 시에도 각 화면의 입력·스크롤 상태가 유지된다.
- **탭 0 — 홈**: 입력 + 최근 기록
- **탭 1 — 기록**: 기록 목록
- **탭 2 — 더보기**: 아카이브·통계·캘린더·설정 진입 허브

### 5.3 기능 흐름 상세 — 입력에서 저장까지
1. **입력** (홈): 자연어 텍스트 또는 이미지. "이번 달 N회", "최근 마셔본 술" 칩 제공.
2. **파싱** (ParseOrchestrator): AI 사용 가능 여부 판단 → Gemini 또는 LocalRuleParser. 로딩 중 취소 가능.
3. **검토** (DraftReviewScreen): 항목별 카드. 마스터 매칭 ✓/⚠, 영문 병기, 추정 수량 경고. 0개 항목 저장 차단, 미래 날짜 입력 차단.
4. **저장** (DrinkLogRepository): 트랜잭션으로 drinkLog + drinkEntry[] + drinkLogFood[] + (선택)tastingNote + parseJob 원자적 저장.
5. **반영**: 홈/목록/캘린더/아카이브/통계 Provider 무효화 → 자동 갱신.

### 6.2 디자인 테마
- **무드**: 위스키 바의 따뜻하고 차분한 분위기
- **컬러**: 라이트 = Jim Beam 앰버(`#B8731A`) + 크림 배경(`#FBF6EE`) / 다크 = Arran Machrie 골드(`#E0A857`) + 피트 블랙(`#15110D`)
- **폰트**: Pretendard (Regular/Medium/SemiBold/Bold), 한글 보조 NotoSansKR
- **테마 토큰**: 간격·반경·모션·색상을 디자인 토큰으로 중앙화(SoT), 다크모드 사용자 선택 지원
- 각 화면은 정상/로딩/에러/빈 상태를 모두 포함

## 8. 기술 아키텍처

### 8.1 레이어 (MVVM)
```
View  →  ViewModel  →  Repository  →  SQLite
(화면)   (상태·로직)    (DB 접근)     (로컬 저장)
```

화살표는 단방향이며, View는 절대 Repository에 직접 접근하지 않는다.

### 8.4 데이터 흐름 (저장)
```
DrinkLogRepository.save()  [단일 트랜잭션]
  ├─ INSERT drinkLog
  ├─ INSERT drinkEntry[]      (id 동기화)
  ├─ INSERT drinkLogFood[]
  ├─ INSERT/UPDATE tastingNote[] (선택)
  └─ INSERT parseJob          (로그)
→ invalidate(logList, calendarLogsByDay, archiveList, stats) → 화면 자동 갱신
```
- **수정(update)**: entry를 삭제·재삽입하지 않고 **id 기준 upsert**한다. 이는 `tastingNote.entryId`의 CASCADE로 인한 노트 유실을 막기 위함이다.

### 8.5 핵심 설계 규칙 (불변)
1. 저장 전 반드시 검토/수정 화면 — 자동 저장 금지
2. AI 로직은 `integrations/parser/` 안에만 — View/ViewModel에 직접 넣지 않음
3. AI 없어도 동작 — LocalRuleParser가 항상 fallback
4. **failure path first** — 정상보다 비정상 복구를 먼저 설계
5. View는 Repository 직접 접근 금지 — ViewModel 메서드만 호출
6. Repository 쓰기 경계는 try-catch + `DatabaseError` 전파(읽기는 raw 통과 허용)
7. 라우팅은 `core/app_routes.dart`의 `Routes` 상수 + `generateRoute`로 중앙 관리(인자 타입 검증, 미지 경로는 `RouteErrorScreen`, 전환은 공통 `fadeSlideRoute`)
8. 개인정보 cleanup — 단건 삭제 시 같은 트랜잭션에서 `parseJob`의 `rawRequest/rawResponse/errorMessage`를 NULL 처리, 전체 삭제 시 행 자체 삭제

## 9. AI 파싱 엔진 상세

### 9.1 ParseOrchestrator 흐름
1. 입력(텍스트/이미지) 수신
2. **AI 사용 가능 판단** — 다음 중 하나라도 실패하면 AI를 건너뜀:
   - AI 비활성(`isEnabled=0`) / keyMode 미일치 / 키 없음
3. AI 가능 시 **GeminiTextParser(또는 이미지)** 호출
4. AI 실패 시 `AppError`로 분류만 하고 **throw하지 않음** → LocalRuleParser로 전환
5. 이미지 경로: AI 실패 → 텍스트 fallback → 없으면 빈 결과(local)
6. 결과(`ParseResult`: entries/foods/warnings) + `parseJobId` + **`wasAiAttempted`** 반환

### 9.2 wasAiAttempted (투명성 플래그)
- 실제 API 호출이 발생했는지 여부. **로컬 경고 배너는 `wasAiAttempted=true`(즉 AI를 시도했으나 실패)일 때만** 표시한다. AI를 애초에 시도하지 않은 경우(비활성)에는 배너를 띄우지 않는다.

### 9.3 Gemini 연동
- **Dio** HTTP 클라이언트, **재시도** 로직, **CancelToken**으로 로딩 중 사용자 취소 지원
- 모델 기본값 `gemini-2.5-flash-lite`(사용자 변경 가능)
- 구조화된 요청/응답 스키마(`gemini_schemas.dart`)로 JSON 파싱

### 9.4 LocalRuleParser
- 마스터 데이터(553종)·별칭·정규식·장소 키워드 사전 기반
- 항상 `ParseResult`(빈 결과 포함)를 반환하며 throw하지 않음 → 최종 안전망

### 9.5 쿼터 정책
- 현재 정책: 사용자가 본인 Gemini API 키를 연결해 사용(개인 한도). 공용 기본 키는 제거됨.
- `usageQuota` 테이블로 일별 사용량(텍스트/이미지)을 기록.

## 10. 외부 연동

### 10.1 Gemini API (선택)
텍스트 초안 생성·이미지 보조·테이스팅 노트 보완. 사용자 개인 Key 연결 시 활성화. 키는 `flutter_secure_storage`에 저장.

### 10.2 Supabase (선택, dormant 패턴)
- **활성 조건**: `.env`(또는 `--dart-define`)에 Supabase URL/anon key가 있고 초기화 성공(`supabaseInitialized=true`).
- **미설정 시**: `supabaseClientProvider`가 null → 모든 서비스 null → 앱은 로컬 전용으로 정상 동작(클라우드 메뉴는 "미설정" 안내).
- **데이터 모델**: 로컬 SQLite가 SoT(Source of Truth). 클라우드는 사용자당 1행 JSON 스냅샷(`drink_backups`).
- **Offline-first 복원**: `fetch → (확인) → wipe → apply`. 네트워크 실패 시 로컬 무손상, 복원은 단일 트랜잭션 교체(실패 시 롤백). 로컬 스키마 변경 없음.
- **인증 보안**: `AuthException`을 `ValidationError`/`NetworkError`로 매핑하며 원문 메시지는 노출하지 않음(PII 보호).

### 10.3 로컬 알림 (4 시나리오)
`flutter_local_notifications` + `timezone`(Asia/Seoul). 단일 채널 `albi_reminder`.
| ID | 시나리오 | 발송 시점 |
|----|---------|----------|
| 100 | 주간 요약 | 매주 일요일 21:00 |
| 200 | 위험 신호(재방문 reminder) | 3일 미기록 시 |
| 300 | 새벽 음주 다음날 입력 | 입력 시각 0~5시 → 같은 날 14:00 |
| 400 | 주간 건강 신호 | 주간 표준잔 초과 시 일요일 19:00 |
알림 권한은 플러그인 내장 API로 요청(iOS `requestPermissions`, Android 13+ `requestNotificationsPermission`).

## 11. 비기능 요구사항

### 11.1 개인정보 보호
- AI 원문(`parseJob.rawRequest/rawResponse/errorMessage`)은 민감 정보. **단건 기록 삭제 시 같은 트랜잭션에서 NULL 처리**, **전체 초기화 시 행 자체 삭제**.
- 비밀 키(Gemini)는 인앱 보안저장소(secure storage) 우선. `.env`에는 공개 안전값(Supabase anon key)만 둔다.

### 11.2 에러 처리 — sealed AppError
`lib/core/exceptions.dart`의 `sealed class AppError` + 4 하위 클래스:
- `DatabaseError` — sqflite 쓰기 실패
- `NetworkError(statusCode)` — Dio/API 실패
- `ParseError` — 입력 파싱 실패
- `ValidationError` — 입력 검증 실패

Dart 3 sealed → switch가 **exhaustive**(누락 시 컴파일 에러로 감지). 단건 API 호출은 interceptor/경계에서 처리하므로 불필요한 try-catch를 두지 않는다.

### 11.3 실패 복구 (failure-path first)
- AI 실패 → 로컬 파서 / 네트워크 실패 → 로컬 무손상 / 복원 실패 → 트랜잭션 롤백 / 잘못된 라우트 → RouteErrorScreen.
- 전역 에러는 `main.dart`의 Zone 핸들러로 포착.

### 11.4 접근성 / 입력 검증
- 48dp 탭 타깃, StarRating Semantics(TalkBack/VoiceOver), Source 뱃지 WCAG AA 대비
- 미래 날짜 입력 차단, 0개 항목 저장 차단, 추정 수량 경고

### 11.5 성능
- `IndexedStack` 탭 유지로 재진입 비용 절감, 인덱스 7개로 조회 최적화, 시드 64KB 1회 적재.

## 12. 건강 인사이트 (표준잔)

- 한국 기준 **1 표준잔 = 순알코올 8g**(WHO 권고/한국주류협회 기준). `standard_drink_utils.dart`에서 도수·수량으로 순알코올량을 환산.
- 환산 결과로 주간 과음 신호를 감지하고, 통계 화면(카테고리 파이차트 등)과 주간 건강 알림(시나리오 400)에 활용.
- 본 기능은 참고용 신호이며 의학적 판정이 아니다(§2.4 범위 제외).
