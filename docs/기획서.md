## 1. 프로젝트 개요

**Albi (알비, 알코올 비서)** — 자연어 한 줄 입력만으로 음주 기록을 만들어 주는 모바일/데스크톱 앱.

| 항목 | 내용 |
|------|------|
| 과목 | 모바일 앱 프로그래밍 (2026 봄학기) |
| 팀 | 김태겸 (파싱/DB), 곽지한 (UI/디자인) |
| 기간 | 2026-03-30 ~ 2026-05-10 |
| 플랫폼 | Android / iOS / Windows / macOS / Linux / Web (Flutter 단일 코드베이스) |
| 저장소 | [github.com/RoastFried-RF/Albie](https://github.com/RoastFried-RF/Albie) |

## 2. 문제 정의

### 기존 음주 기록 앱의 문제
1. **입력 마찰** — 주종/수량/장소/안주를 각각 별도 필드로 입력 → 한 번에 여러 번의 탭 + 스크롤
2. **학습 장벽** — "잭다니엘", "잭 다니엘", "잭다니엘스" 등 동일 브랜드의 다양한 표기를 수용하지 못함
3. **저장 사고** — 잘못 입력해도 자동 저장되어 되돌리기 힘듦
4. **AI 강제성** — AI 없으면 사용 불가하거나, 개인 API 키 요구

### Albi 의 해결 접근
- **한 줄 자연어 입력** + AI(또는 로컬 규칙) 파싱으로 입력 마찰 최소화
- **별칭 풍부한 마스터 데이터** (553종, 70% 한국어 라벨) 로 다양한 표기 흡수
- **저장 전 반드시 검토 화면** — 자동 저장 금지, 수정 후 명시적 저장
- **이중 파서** — AI 없어도 LocalRuleParser 로 동작, AI 는 정확도 개선 옵션

## 3. 타겟 사용자

### Primary Persona
- **20~40대 한국인** — 모바일 네이티브, 한국어로 주류명 입력하는 사용자
- 주 1~3회 음주 기록
- 위스키/맥주/와인/소주 등 다양한 주종 경험

### User Jobs (Jobs-to-be-Done)
1. "어제/오늘 뭐 얼마나 마셨는지 빠르게 남기고 싶다"
2. "내가 마셔본 브랜드 기록/아카이브를 보고 싶다"
3. "최근 음주 빈도/양을 직관적으로 파악하고 싶다"
4. "AI 가 있으면 편하고, 없어도 수기로는 되면 좋겠다"

## 4. 핵심 가치 / 차별화

| # | 차별화 | 구체적 구현 |
|---|--------|-------------|
| 1 | **한 줄 입력** | `"나 오늘 벤로막 15 두 잔 마셨어"` → ParseOrchestrator → DraftReviewScreen |
| 2 | **AI 이중화** | GeminiTextParser 실패 시 LocalRuleParser 로 자동 fallback, 앱 기능 유지 |
| 3 | **검토 필수** | DraftReviewScreen 경유하지 않으면 DB 저장 불가 |
| 4 | **마스터 데이터** | 553종 주류 (한국어 70%), 브랜드 매칭 시 ABV 자동 주입 |
| 5 | **오프라인 우선** | sqflite 로컬 DB, 네트워크 불필요한 핵심 경로 |
| 6 | **프라이버시** | 개인 API 키는 `flutter_secure_storage` (Keystore/Keychain) 에만 저장, 서버 전송 없음 |

## 6. 사용자 흐름

### 6.1 온보딩 (초회)
```
앱 시작
  → OnboardingScreen (3페이지 스와이프)
    ├─ 페이지 1: "한 줄만 입력하면 기록이 돼요"
    ├─ 페이지 2: "AI 없이도 동작해요"
    └─ 페이지 3: "저장 전 항상 검토하세요"
  → SharedPreferences 에 완료 플래그 저장
  → AppShell (홈 탭)
```

### 6.2 음주 기록 작성 (핵심 플로우)
```
HomeScreen
  ├─ 자연어 입력 ("벤로막 15 두 잔")
  │   → HomeViewModel.generateDraft()
  │     → ParseOrchestrator.process()
  │       ├─ AI 가능? → GeminiTextParser → ParseResult
  │       └─ 실패/비활성 → LocalRuleParser → ParseResult
  │     → DraftReviewScreen
  │
  └─ 수기 입력 버튼 → DraftReviewScreen (빈 초안)
      ├─ 주류 Entry 추가/삭제 (brand, age, 수량, 단위, ABV)
      ├─ 장소, 안주, 전체 메모 편집
      ├─ 마신 날짜/시각 편집 (새벽 6시 이전 = 전날 처리)
      └─ 저장 → DrinkLogRepository.save() (트랜잭션)
         → 홈/목록/아카이브/통계 Provider invalidation
         → 홈으로 귀환
```

### 6.3 조회/관리
```
LogListScreen (목록)
  ├─ 최신순 무한 스크롤 (페이지당 20건)
  ├─ 검색 (원문/주류명/장소/안주 OR 검색)
  └─ Long-press → 삭제 확인

LogDetailScreen (상세)
  ├─ Entry 목록 + 시음 노트
  ├─ 편집 → DraftReviewScreen (editing mode)
  └─ 삭제 → 확인 다이얼로그

ArchiveScreen (아카이브)
  ├─ 마셔본 주류 집계 (DISTINCT liquorMasterId)
  ├─ 카테고리 필터 (위스키/맥주/와인/...)
  └─ 즐겨찾기 토글

StatsScreen (통계)
  ├─ 최근 N일 요약
  ├─ 주종별 분포 파이차트
  └─ 주간 패턴

SettingsScreen
  └─ AiSettingsScreen
      ├─ AI 활성화/비활성화
      ├─ 키 모드: app_default (기본 키) vs user_provided (내 키)
      ├─ 모델 선택: gemini-2.5-flash-lite (기본) / gemini-2.5-flash
      └─ 키 검증 테스트
```

## 7. 데이터 모델

### 7.1 주요 엔티티 (DB 테이블 8개)

| 테이블 | 주 필드 | 설명 |
|--------|---------|------|
| `drinkLog` | id, rawInputText, parseSource, place, drankAt, overallMemo | 음주 세션 단위 |
| `drinkEntry` | logId, liquorMasterId, liquorNameRaw, quantityValue, quantityUnit, alcoholPercent, ageStatement | 세션 내 개별 주류 |
| `drinkLogFood` | logId, foodName | 세션 내 안주 (N:1) |
| `liquorMaster` | canonicalName, nameKo, aliasesJson, category, subcategory, defaultAbv, country, distillery, isFavorite | 주류 마스터 (553종) |
| `tastingNote` | entryId (UNIQUE), nose, palate, finish, rating, note | Entry 당 1개 시음 노트 |
| `parseJob` | logId, sourceType, parserUsed, status, rawResponse, errorCode, durationMs | 파싱 이력/감사로그 |
| `aiConfig` | provider, keyMode, selectedModel, isEnabled, lastErrorMessage | AI 설정 (id=1 단일행) |

### 7.2 관계 다이어그램
```
drinkLog 1 ── N drinkEntry ── 0..1 tastingNote
    │                │
    │                └─ N:1 ─ liquorMaster
    │
    └── N drinkLogFood
    └── 1 parseJob (optional)

aiConfig (single row)  usageQuota (per day)
```

### 7.3 주요 enum 값
- `parseSource`: `ai_user_key` / `ai_app_key` / `local_parser` / `manual`
- `quantityUnit`: `glass` / `bottle` / `can` / `shot` / `ml`
- `category`: `whisky` / `wine` / `beer` / `spirit` / `soju` / `makgeolli` / `sake` / `cocktail` / `highball`
- `keyMode`: `none` / `app_default` / `user_provided`

## 8. AI / 파서 전략

### 8.1 ParseOrchestrator 분기
```
ParseInput (text / image)
   │
   ├── image 입력? → LocalRuleParser 전용 (OCR 미구현)
   │
   └── text 입력
       ├─ AI 활성화 + 키 가용 + 쿼터 남음?
       │    ├─ YES → GeminiTextParser
       │    │         ├─ 성공 → ParseResult 반환
       │    │         └─ 실패 → _classifyAiError → aiConfig 에 메시지 저장 → null
       │    └─ NO → skip
       │
       └─ null 반환되면 → LocalRuleParser (항상 fallback)
```

### 8.2 에러 타입 (sealed AppError)
- `DatabaseError` — 로컬 DB 쓰기 실패
- `NetworkError(statusCode)` — API 실패 (401 키 유효성, 429 쿼터, timeout)
- `ParseError` — 입력 파싱 실패
- `ValidationError` — 사용자 입력 검증 실패

### 8.3 사용량 쿼터 정책
| 키 유형 | 텍스트 | 이미지 |
|---------|--------|--------|
| `app_default` (앱 기본 키) | **10회/일** | **3회/일** |
| `user_provided` (사용자 키) | 무제한 | 무제한 |

쿼터 초과 시 UI 안내 + 로컬 파서로 자동 전환.

## 11. 비기능 요구사항

### 성능
- DB 배치 로딩 (N+1 쿼리 해소) — getAll/search 호출 시 entries/foods 를 IN 절로 한 번에 조회
- 인덱스: drankAt / logId / liquorMaster category·nameKo / parseJob createdAt
- 앱 초기화: DB 인스턴스 lazy (FutureProvider)

### 보안
- API 키는 `flutter_secure_storage` 에만 저장 (Android Keystore / iOS Keychain)
- 로그에 키 원문 노출 금지
- 서버 미사용 — 모든 데이터 로컬

### 접근성
- Material 3 색상 시스템 + 다크 모드 자동 대응
- NotoSansKR 폰트 번들 (한글 렌더링 일관성)
- 의미 있는 아이콘 + Tooltip (향후 보강)

### 오프라인
- 핵심 경로 (기록 작성 → 저장 → 조회) 는 네트워크 불필요
- AI 는 선택 옵션

### 데이터 무결성
- `drinkLog.save/update/delete` 는 트랜잭션 + `DatabaseError` 전파
- 외래 키 `PRAGMA foreign_keys = ON`
- `drinkLog` 삭제 시 `drinkEntry` / `drinkLogFood` CASCADE

## 12. 기술 스택

| 계층 | 기술 |
|------|------|
| 언어 | Dart 3 (sealed class, pattern matching) |
| 프레임워크 | Flutter 3.41.6 (stable) |
| 상태관리 | `flutter_riverpod ^2.6.1` (StateNotifier + AsyncNotifier) |
| 로컬 DB | `sqflite ^2.4.2` (+ `sqflite_common_ffi` 데스크톱) |
| HTTP | `dio ^5.7.0` (Gemini REST) |
| Secure Storage | `flutter_secure_storage ^9.2.4` |
| SharedPrefs | `shared_preferences ^2.3.4` (온보딩 플래그) |
| 국제화 | `intl ^0.20.2` (날짜 포맷) |
| 폰트 | NotoSansKR (번들) |
| 테스트 | `flutter_test` + `integration_test` (37 유닛/위젯 + 3 golden + 1 E2E) |
| 데이터 파이프라인 | Python 3.10 (Wikidata SPARQL 시드 생성) |

**아키텍처**: MVVM — View → ViewModel → Repository/Integration → Entity
- 구현체 1개면 인터페이스 생략
- View 는 Repository 직접 접근 금지 (ViewModel 경유)
- Repository 쓰기 경계는 try-catch + DatabaseError
