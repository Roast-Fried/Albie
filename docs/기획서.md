## 1. 앱 개요

### 1.1 기획 배경
술을 마신 뒤에는 무엇을 얼마나 마셨는지 금방 흐려진다. 특히 위스키처럼 브랜드·연산·도수 차이가 큰 술은 나중에 기억만으로 정리하기 어렵다. **알비**는 사용자가 *"나 벤로막 15년 2잔 마셨어"* 처럼 짧은 문장만 입력해도 기록 초안을 만들고, 필요하면 이후 수동 테이스팅 노트와 아카이브로 정리할 수 있도록 설계한 **로컬 중심 음주 기록 앱**이다. 기본적으로는 단말 내 데이터와 간단한 규칙 기반 파싱으로 동작하고, 원하면 사용자가 직접 AI를 연결해 텍스트·이미지 기반 자동 기록 품질을 높일 수 있다.

### 1.2 핵심 타깃
- 위스키를 중심으로 마셔본 술을 차곡차곡 기록·회고하고 싶은 사용자
- 술자리 후 "뭘 마셨는지" 자주 잊는 사용자
- 복잡한 커뮤니티보다 빠른 입력과 개인 아카이브를 선호하는 사용자

### 1.3 범위 제외
- 회원가입/로그인, 서버 백엔드, 실시간 동기화, 소셜 피드
- 실제 체내 알코올 농도 측정, 건강 판정, 음주 가능 여부 판단
- 대규모 클라우드 동기화, 정교한 추천 엔진, 완전 자동 판정형 이미지 인식

### 5.2 상태 관리
- **Riverpod** 채택 — 홈 입력값 / 파싱 결과 / AI 연결 / 기록 목록 / 아카이브 상태가 서로 얽혀 있어 명시적 분리가 필요.
- 로컬 DB 접근과 UI 분리가 쉽고 과제 범위에서 복잡도 과대 방지.
- Provider 전체 목록: `/docs/기획서-부록.md` 또는 [CLAUDE.md](../CLAUDE.md) 참조

### 5.3 데이터 저장
- **sqflite**: 기록 원본, 테이스팅 노트, 아카이브 집계 데이터, 초기 적재 술 데이터
- **shared_preferences**: 앱 설정, 정렬, 알림, 최근 입력 환경
- **flutter_secure_storage**: 사용자 AI Key 및 민감 설정

**주류 마스터 데이터**: 553종 (위스키/와인/맥주/스피릿/사케/소주/막걸리/칵테일), 한국어 라벨 70%, 64KB. [tools/seed_generator/](../tools/seed_generator/) 로 Wikidata SPARQL + 큐레이션 병합 재생성 가능.

### 5.5 아키텍처 — MVVM + Riverpod
```
lib/
├── views/                # Screen + Widget (Consumer/ConsumerStateful)
│   └── common/           # 공통: ErrorStateWidget, DeleteConfirmDialog
├── viewmodels/           # Riverpod StateNotifier / AsyncNotifier
├── domain/entities/      # POJO 데이터 클래스 (6종)
├── data/                 # Repository 5종 (sqflite 직접)
├── integrations/         # AI 어댑터
│   ├── parser/           # LocalRuleParser, GeminiTextParser, ParseOrchestrator
│   └── gemini/           # GeminiClient
└── core/
    ├── database/         # 초기화 + SeedLoader
    ├── utils/            # label_utils, korean_number, date_utils
    ├── exceptions.dart   # sealed AppError (DatabaseError/NetworkError/ParseError/ValidationError)
    └── providers.dart    # 공유 Providers
```

**핵심 규칙**:
1. 저장 전 반드시 검토/수정 화면 — 자동 저장 금지
2. AI 로직은 `integrations/parser/` 안에만
3. AI 없어도 동작 — LocalRuleParser 가 항상 fallback
4. failure path first — 정상보다 비정상 복구 우선
5. View 는 Repository 직접 접근 금지 — ViewModel 메서드 호출만
6. Repository 쓰기 경계는 try-catch + `DatabaseError` 전파
