# 학습성찰 보고서 — 알비(Albi)

> 모바일프로그래밍 프로젝트 학습성찰 (OT.txt 루브릭 항목).
> 팀: 김태겸(파싱/DB) · 곽지한(UI/디자인). 기간: 2026-03-30 ~.

## 1. 프로젝트 개요

자연어 한 줄로 음주를 기록하는 Flutter 앱. AI(Gemini) 연결 시 정밀 파싱, 미연결 시
로컬 규칙 파서로 fallback 하여 **AI 없이도 동작**한다. MVVM + Riverpod + sqflite 로
구성하고, 자동저장을 금지해 반드시 검토 화면을 거치도록 설계했다.

## 2. 진행 과정

| 단계 | 내용 |
|------|------|
| 기획 | 기획서 작성(MVP 5 + 선택 9), 와이어프레임 13화면 |
| 기반 | MVVM 골격 + sqflite 8테이블 + 시드(술 553종) |
| 핵심 구현 | 파서(AI/로컬) → 검토 → 저장, 테이스팅 노트, 아카이브 |
| UX 완성 | 통계 차트, 캘린더, 알림, 애니메이션, 다크모드 |
| 강의 정합 | Named Routes/onGenerateRoute, `.env`, Supabase 백업, **Drift 데모**, SDD 산출물 |
| 디자인 | 디자인 시스템 토큰화 + 런처 아이콘/스플래시 + 빈상태 일러스트 + 전체 리디자인 |
| 검증 | 단위/위젯 테스트 + 골든 + 통합 캡처 + Codex 페어 리뷰 |

## 3. 마주친 문제와 해결

1. **파싱 정확도** — 자연어는 변형이 많다. → 로컬 규칙 파서 + 선택적 AI 이중화, 한글 수량("반 병"/"열두") 회귀 테스트로 경계 방어.
2. **개인정보** — AI 원문이 DB에 남는 문제. → 단건 삭제 시 같은 트랜잭션에서 parseJob 원문 NULL, 전체 삭제 시 행 삭제.
3. **상태 유지** — 탭 전환 시 입력/스크롤 소실. → IndexedStack 으로 3탭 유지, provider autoDispose 미사용 정책.
4. **에러 일관성** — 흩어진 예외 처리. → sealed AppError 4종 + write 경계 try-catch, read raw 통과.
5. **강의 기법 정합** — 강의는 Drift/FutureBuilder/StreamBuilder 를 가르치나 앱은 Riverpod 으로 대체. → 메인은 안정성 위해 sqflite 유지, **컨디션 로그를 Drift 격리 데모**로 추가해 watch()+StreamBuilder+FutureBuilder 를 실제 동작으로 시연(앱 안정성과 학습 시연 양립).

## 4. 강점

- **failure-path-first**: AI 실패/취소(CancelToken)/네트워크/DB 오류 복구 경로를 정상 경로보다 먼저 설계.
- **테스트 자산**: 단위/위젯 145+ + 골든 + 통합 캡처 + Codex 페어 리뷰 게이트.
- **접근성**: 48dp 터치 타깃, WCAG AA 대비, Semantics 라벨(별점/배지) 보강.
- **아키텍처 일관성**: View→ViewModel→Repository 경계, AI 로직 격리.

## 5. 개선점 / 한계

- 메인 DB 를 Drift 로 전면 전환하지 않음(리스크 회피) — 데모로 역량만 시연.
- Supabase 클라우드 백업은 `.env` 미설정 시 dormant(라이브 백엔드 e2e 미검증).
- 일부 화면의 ViewModel 안티패턴(WidgetRef 전달) 잔여 — 후속 정리 대상.

## 6. 기능 달성도

기획서 MVP 5/5 + 선택 9/9 + 강의 정합 추가(라우팅/캘린더/백업/Drift) 완료.
와이어프레임 정합 39/39. 본 사이클에서 디자인 시스템 + 아이콘 + SDD 산출물 추가.

## 7. 배운 점

- AI 페어(Claude+Codex)로 **계획→적대적 검토 수렴→구현**의 SDD 사이클이 단독 구현보다
  결함을 일찍 잡는다(본 사이클도 Codex R1 6 HIGH 를 구현 전 수렴).
- 강의의 "AI가 기획을 타협하게 두지 말 것" 원칙을 따라, 기획 품질을 유지하며 구현만 가속.
